# Аккаунты, наработки и ролики

Один аккаунт — один рабочий контекст. В нём могут быть мультсериал, личный бренд,
обучающие видео или другой формат. Для каждого аккаунта есть папка
`video/accounts/<account>/`; отдельные ролики остаются в `video/projects/<id>/`.
Базы данных, активного глобального профиля и отдельного уровня «серия» нет.

## Что хранить

| Место | Содержимое |
|---|---|
| `account.json` | Название, площадка, хэндл и `defaults` для создания роликов |
| `SOURCE.md` | Краткий паспорт, принятые решения, ссылки на нужные наработки и состояние работы |
| Остальные документы аккаунта | Только нужное ему: персонажи, редакционные правила, монтажные предпочтения, ссылки на проверенные сцены и результаты |
| `references/` | Исходные брифы и визуальные референсы, если они есть |
| `assets/` | Переиспользуемые модели, изображения, голоса/звуки, шрифты; описание происхождения рядом или в паспорте |
| `video/projects/<id>/` | Самостоятельный выпуск: выбранные настройки, сцены, копии нужных медиа, экспорт и результаты публикации |

Не нужно создавать одинаковый набор пустых документов для всех аккаунтов.
У сериала могут быть `CHARACTERS.md` и модели героев; у личного бренда —
монтажные предпочтения, логотип, проверенные титры и примеры выступлений.
Повторно используемый код сцены пока можно хранить в рабочем выпуске и ссылаться
на него из паспорта. Для нового ролика агент переносит нужный код и зависимости;
автоматического импорта произвольного TSX из аккаунта нет.

## Выбор контекста

Для нового ролика агент определяет аккаунт из запроса. Если определить нельзя,
уточняет; для явно самостоятельной задачи аккаунт не требуется. Для существующего
ролика привязка находится в `project.json.account`. Несовпадение с новым запросом
нужно разрешить до применения настроек. Не делаем скрытого переключения аккаунта.

Читаем только `SOURCE.md` выбранного аккаунта и документы, нужные текущей задаче.
Например, монтаж речи не требует загружать все прошлые метрики, а сценарий мультфильма —
наработки личного бренда. Старые корневые `brand-kit.md`, `harness.config.json`,
`exemplars.md` не используются как настройки всех аккаунтов.

Приоритет: текущий запрос → принятые решения ролика → выбранный аккаунт → нейтральный
технический шаблон. Стиль другого аккаунта переносится только по явной задаче.

## Команды

```sh
python reel.py accounts
python reel.py account-new channel-id --title "Название аккаунта" --platform instagram --handle "@channel-id" --brief "Концепция и требования" --width 1080 --height 1920 --fps 30
python reel.py new episode-001 --account channel-id --title "Название" --seconds 20
python reel.py list --account channel-id
python reel.py asset episode-001 characters/hero.glb
```

`account-new` создаёт `account.json`, заполненный переданными сведениями `SOURCE.md`
и папку `assets/`. Существующий аккаунт не перезаписывает. ID состоит из 1–64 строчных
латинских букв, цифр, дефисов или подчёркиваний (первый символ — буква/цифра).
Неизвестные площадка и хэндл остаются `null`, технические настройки без флагов — пустыми.
Агент сразу дополняет паспорт из запроса и приложенных материалов, сохраняет нужные
референсы и создаёт только содержательные документы наработок. Неизвестное отмечает
как нерешённое, без обязательного интервью обо всех параметрах.

Например, можно попросить: «Заведи аккаунт @channel-id: короткие диалоги двух героев
о науке, вертикальные видео. Вот описание персонажей». Агент создаёт отдельный аккаунт,
сохраняет описание героев и связывает следующие ролики с этим аккаунтом.

Полученный `account.json` можно редактировать напрямую:

```json
{
  "title": "Название аккаунта",
  "platform": "instagram",
  "handle": "@channel-id",
  "defaults": {
    "width": 1080,
    "height": 1920,
    "fps": 30
  }
}
```

Это пример технических значений, а не обязательные параметры каждого аккаунта.
`defaults` поддерживает `width`, `height`, `fps`, `fontFamily`, `colors`
(`background`, `foreground`, `accent`, `muted`) и `audio` (`lufs`). Неизвестные ключи
отклоняются, чтобы настройки не выглядели рабочими, когда код их не использует.
Поведение персонажей, голоса, стили титров и режиссура описываются в документах
и реализуются в композиции конкретного ролика; одного произвольного поля JSON недостаточно.

При `new --account` значения аккаунта накладываются на технический шаблон,
а явные `--width`, `--height`, `--fps` имеют приоритет. Полученный результат записывается
в `project.json` вместе с `account`; ссылка на паспорт добавляется в `SOURCE.md`.
Неуказанные цвета и шрифт остаются техническими значениями стартовой композиции,
а не утверждённым стилем аккаунта. Длительность задаётся выпуску через `--seconds`
(без флага — 12 секунд стартового шаблона), а не наследуется как сценарное решение.

Изменение `account.json` влияет только на последующие создания. Для изменения
существующего ролика редактируй его файлы. Старые ролики без `account` продолжают
работать; привязку можно добавить вручную в их `project.json` и `SOURCE.md`, не меняя
сцены или настройки. CLI не переоформляет их автоматически.

## Материалы и воспроизводимость

Команда `asset` берёт ровно один файл из `assets/` аккаунта, указанного в ролике,
и копирует его в `public/assets/` ролика с именем по хэшу содержимого. Она возвращает
путь для композиции. Пути за пределами выбранной папки отклоняются. Остальная библиотека
не копируется. Для GLTF с внешними текстурами сначала подготовь самодостаточный GLB
или импортируй все зависимости с нужной структурой явно — команда не собирает пакеты.

Замена оригинала в аккаунте не меняет уже импортированную копию. Храни описание
происхождения и использованной версии в `SOURCE.md` ролика. `import` остаётся способом
явно добавить внешний файл; это не автоматическое наследование чужой библиотеки.
Рендер использует локальные параметры и материалы ролика, а не живые настройки аккаунта.

Новый шаблон и `video/src/project/` используют нейтральные анимационные примитивы.
Старые оформленные элементы `video/src/ui/` и демо могут читать `harness.config.json`:
при переносе такой сцены сделай её оформление локальным. Произвольный TSX остаётся
кодом, поэтому это разделение рабочего контекста, а не песочница доступа к файлам.

Результаты и интеграции хранятся у выбранного аккаунта/ролика. Хэндл в профиле не
доказывает подключение сервиса; перед публикацией или выгрузкой сверяй реальный целевой
аккаунт. Секреты остаются вне документов и Git. Личные папки аккаунтов, сценарии и медиа
не включаются в публичные обновления системы. Публичные примеры используют только
синтетические или отдельно разрешённые материалы.
